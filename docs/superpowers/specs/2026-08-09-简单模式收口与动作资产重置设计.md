# 简单模式收口与动作资产重置设计

## 背景与根因

当前阶段只继续完善简单模式动作工坊，但页面仍显示简单/复杂模式切换入口，用户浏览器中也保留了此前创建和复制的自定义动作。

问题由两个独立原因造成：

- 复杂模式入口此前只完成设计文档，没有提交实际布局代码。
- Studio 资产保存在各浏览器配置文件自己的 `localStorage` 中。Codex 内置浏览器与用户截图所用浏览器不是同一配置文件，因此前者显示 0 个自定义动作，不能证明后者的数据已清除。

## 目标

- 实际隐藏 Studio 顶部完整的模型模式切换控件。
- 保留复杂模型底层代码、持久化结构和已有复杂配方，不删除或迁移复杂模型数据。
- 所有浏览器首次加载新版资产格式时，一次性清空旧自定义动作。
- 保留自定义道具、内置动作模板和扩展运行时行为。
- 迁移完成后，新创建的动作继续正常持久化，不在后续刷新时重复清空。

## 方案

### 模式入口

在 Studio 布局中保留现有 `StudioModelModeSwitch` 接线，但增加固定关闭的局部显示门禁。组件不渲染，因此顶部不再出现“简单模型 / 复杂模型”按钮；底层双模型能力保持可恢复。

### 一次性动作资产重置

把当前 Studio 资产键从 `yk-pets:studio:assets:v2` 升级到 `yk-pets:studio:assets:v3`，并把 v2、v1 作为历史键：

1. 已存在 v3 时，按正常流程恢复动作和道具。
2. 不存在 v3、但存在 v2 或 v1 时，读取历史数据，仅迁移规范化后的道具，把动作列表写为空数组。
3. 成功写入 v3 后移除历史键，防止旧动作再次恢复。
4. 动作工坊发现当前会话仍指向已不存在的动作时，清空选中动作 ID。

该迁移只执行一次。之后用户重新创建的动作写入 v3，并正常跨刷新保留。

## 验证

- 回归测试证明历史资产迁移后动作为空、道具保留，v3 当前资产不会被重复清空。
- 静态门禁证明 Studio 布局的切换入口显示门禁处于关闭状态。
- 类型检查和生产构建通过。
- 浏览器首次加载新版后，资产库显示 0 个自定义动作，动作工坊不再展示旧动作，顶部不显示模型模式切换控件。

## 回滚

- 重新开启布局显示门禁即可恢复模型模式切换入口。
- 代码可以继续读取 v3 新动作；被用户明确要求清除的旧自定义动作不提供自动恢复。
