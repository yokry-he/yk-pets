# 现代化直接动作操控设计

## 1. 背景与问题

当前简单模式已经把动作创建改造为“选择动作意图→编辑阶段→直接播放”，但阶段姿势仍主要通过身体部位树、移动/旋转/缩放/语义模式和数值行编辑。它虽然比专业时间轴简单，实际操作仍接近参数面板：用户必须先在列表中找到部位，再理解变换模式和多个数值，3D 宠物没有成为主要编辑入口。

本轮目标是让不会绑定、蒙皮和专业动画的新手通过“点击宠物、选择移动或旋转、直接拖动”完成姿势设计，同时保留每个身体部位的完整参数控制。快速姿势卡用于提供自然起点，直接拖拽用于自由创作，固定属性栏用于精确调整；三者必须操作同一份阶段姿势数据。

## 2. 目标与成功标准

### 2.1 目标

- 3D 宠物成为简单模式的主要动作编辑入口，身体部位树不再占据默认操作中心。
- 用户选中部位后明确选择“移动”或“旋转”，随后直接拖拽该部位完成姿势修改。
- 移动手脚时自动保持肩肘、髋膝和身体连接；旋转时围绕合法关节中心并遵守安全角度。
- 快速姿势卡只提供自然起点，应用后仍可继续拖拽和调整全部参数。
- 模型旁的轻量浮动工具与固定属性栏同时存在，并共享选择、模式和参数状态。
- 默认使用直观中文语义参数，精确 X/Y/Z 参数收进可展开区域。
- 所有修改继续写入当前阶段配方，并复用现有编译、撤销、自动保存和播放链路。

### 2.2 成功标准

- 用户最多通过“选择阶段→点击部位→选择移动/旋转→拖动”完成一次有效姿势修改。
- 点击模型、姿势卡、滑杆和精确输入四种入口始终显示相同结果，不产生互相覆盖的独立状态。
- 一次完整拖拽只生成一个撤销记录，撤销后恢复拖拽开始前的阶段姿势。
- 手脚拖到不可达位置时被安全钳制，不出现肩膀脱离、肢体断层、骨骼拉长或非有限数值。
- 画布旋转与部位操控具有明确模式，不争抢同一次指针操作。
- 1440×900 和 760×900 均无页面横向溢出，只有一个 3D Canvas。

## 3. 已比较方案与结论

### 3.1 方案一：分层直接操控

点击 3D 部位后选择移动或旋转，直接拖拽；右侧显示完整参数。自由度高且直观，但完全从零摆姿势仍需要较多操作。

### 3.2 方案二：专业 Gizmo

使用三轴箭头和旋转环。精确且接近 Blender/Maya，但会重新引入坐标轴、局部空间和关节知识，不符合新手优先目标。

### 3.3 方案三：姿势卡与滑杆

通过“抬手、展开、弯曲、挥手”等姿势卡快速改变部位。学习成本最低，但单独使用会限制自由创作。

### 3.4 采用结论：方案一与方案三组合

默认以分层直接操控为主，姿势卡作为选中部位的快速起点。用户可以先套用自然姿势，再选择移动或旋转进行拖拽，最后用右侧语义参数或精确 X/Y/Z 微调。专业 Gizmo 不进入简单模式，继续由高级编辑承担精确专业工作。

## 4. 核心操作流程

1. 用户选择或新建动作，并在阶段条中选择当前阶段。
2. 用户点击 3D 宠物的头部、身体、手、脚、耳朵或尾巴；系统高亮选中部位。
3. 模型旁出现轻量浮动工具，只显示部位名称、“移动”“旋转”和复位入口。
4. 右侧固定属性栏同步切换到当前部位，显示快速姿势、当前模式的语义参数、对称编辑和精确参数折叠区。
5. 用户可以先点击姿势卡，也可以直接选择移动或旋转并拖拽部位。
6. 拖拽期间实时预览；释放指针后一次性提交当前阶段、重新编译动作并创建一个撤销记录。
7. 用户播放整个动作检查阶段衔接；500ms 无新修改后自动保存。

“姿势卡→拖拽→参数微调”不是三个独立步骤，用户可以任意跳过或交替使用。

## 5. 界面与交互设计

### 5.1 3D 画布

- 可编辑部位具有语义拾取区域；悬停时显示轻量轮廓，点击后显示明确选中高亮。
- 未选部位时，拖动画布继续控制预览视角；选中部位后，只有从选中部位或其操控柄开始的拖动才编辑姿势，画布空白区域仍旋转视角。
- 选中部位附近显示浮动工具，但自动避开画布边缘和宠物脸部。浮动工具只承担高频操作，不承载完整参数。
- 移动和旋转互斥。当前模式使用文字和图形双重表达，不能只靠颜色区分。
- 拖拽时显示目标点、运动方向和可达边界；被钳制时显示“已到安全范围”而不是技术错误。
- `Escape` 取消当前拖拽，点击画布空白取消部位选择；切换阶段、动作或编辑模式前先结束或取消拖拽。

### 5.2 快速姿势卡

- 姿势卡按当前部位和动作意图动态提供，例如手部可提供抬手、展开、弯曲、挥手，身体可提供前倾、后仰、侧倾、扭转。
- 姿势卡写入当前阶段的语义控制值，不写具体骨骼名，不创建隐藏动画层。
- 应用姿势卡是一个独立可撤销事务；之后的拖拽和参数修改继续基于应用后的结果。
- 卡片呈现动作名称和简化图形，不默认展示角度或坐标。
- 当前体型不支持的姿势卡不显示；部分支持时只写入可用控制，并用简短文案说明已自动适配。

### 5.3 固定部位属性栏

属性栏始终固定在工作区右侧，避免参数面板随部位跳动。主要结构为：

1. 当前部位名称、对称编辑和恢复部位；
2. 快速姿势卡；
3. 移动或旋转模式；
4. 当前模式的语义参数；
5. 可展开的精确参数；
6. 自动保持连接、平衡或接触的结果说明。

默认参数使用直观中文：

- 移动：左右位置、抬高/降低、前后位置；
- 旋转：前后摆动、向内/向外展开、扭转；
- 肢体特有参数：弯曲、伸展、脚尖方向、肩/髋跟随；
- 附属部件：耳朵张开、耳朵倾斜、尾巴抬高、尾巴摆动和卷曲。

“精确参数”展开后才显示 X/Y/Z 数值、单位和步进按钮。它与语义参数是同一控制值的不同显示方式，不维护第二份数据。

### 5.4 对称编辑

- 简单模式默认单选一个部位，不提供任意多选。
- 具有左右伙伴的部位显示“对称编辑”。开启后，移动和旋转按现有语义镜像规则同步另一侧。
- 不具有对称伙伴的部位不显示该选项。
- 需要任意多选和批量关键帧编辑时进入高级编辑。

### 5.5 窄屏

- 760px 及以下保持 3D 画布为第一操作区域。
- 固定右侧属性栏改为底部抽屉，默认只显示当前部位、移动/旋转和三个常用参数；向上展开后显示姿势卡和精确参数。
- 浮动工具继续位于选中部位附近，并根据安全区自动翻转方向。
- 阶段条保持横向滚动，不压缩阶段名称和操作按钮。

## 6. 领域模型与能力描述

### 6.1 部位操控能力

在现有 `MotionBodyPartDefinition` 与 `MotionControlDefinition` 之上增加可查询的简单操控能力，不在 UI 中硬编码云狐部位：

- 可拾取语义部位与渲染节点的映射；
- 支持的直接模式：移动、旋转；
- 该模式使用的主控制和辅助控制；
- 可拖动末端、关节中心、局部轴和安全范围；
- 可用姿势卡；
- 对称伙伴及镜像规则；
- 不支持时的降级原因。

能力由角色 Rig Profile 和渲染适配器共同提供。阶段配方继续只保存 `MotionControlId` 到有限数值的映射，不保存 Three 对象、屏幕坐标或具体骨骼名称。

### 6.2 直接操控会话

编辑 Store 增加临时直接操控会话：

- `selectedBodyPartId`：当前语义部位；
- `directManipulationMode`：`translate | rotate`；
- `dragState`：指针身份、起始命中、起始姿势、当前预览和钳制状态；
- `expandedExactParameters`：精确参数是否展开；
- `partInspectorOpen`：窄屏底部抽屉状态。

`dragState` 只属于会话，不持久化到动作资产。持久化的唯一事实仍是阶段配方及其编译结果。

## 7. 拾取、拖拽与求解

### 7.1 语义拾取

- 渲染器为每个可编辑部位注册稳定拾取身份，射线命中后只返回 `MotionBodyPartId` 和必要的局部命中信息。
- 拾取层不向页面暴露 Three Mesh、Bone 或材质引用。
- 装饰网格可以映射到最近的语义父部位；不可编辑特效、阴影和道具不参与身体拾取。
- 道具占用手部时，仍允许选择手臂，但需要优先显示“正在持有道具”，避免用户误以为手部未响应。

### 7.2 移动模式

- 头部和身体移动转换为对应语义位移控制，并遵守已有控制范围。
- 手脚作为肢体末端目标。屏幕拖动先投影到与当前视角稳定的操控平面，再转换为角色局部目标。
- 肩肘或髋膝通过确定性肢体求解联动；目标超过可达范围时钳制到边界，不拉长骨骼。
- 简单模型没有真实蒙皮，但必须通过现有层级与连接参数保持肩膀、手臂、腿和脚的视觉连续。
- 耳朵和尾巴仅开放 Profile 明确声明的安全位移或语义控制，不允许任意脱离父部位。

### 7.3 旋转模式

- 旋转围绕当前部位声明的关节中心或语义中心进行。
- 屏幕拖动解析为部位允许的主旋转和辅助旋转，默认优先使用最符合当前视角的两个自由度。
- 关节限制在求解时生效，不能依赖保存后的归一化才修复反折。
- 精确 X/Y/Z 输入使用同一限制和归一化逻辑，不允许绕过安全范围。

### 7.4 事务语义

1. `pointerdown` 捕获指针并保存不可变起始阶段姿势；
2. `pointermove` 通过纯函数求解临时姿势，只更新预览，不写撤销栈和本地存储；
3. `pointerup` 将最终有限姿势作为一次阶段更新提交；
4. `pointercancel`、`Escape`、失焦或求解阻塞恢复起始姿势；
5. 提交成功后由现有阶段编译器重建基础轨道，并调度 500ms 自动保存。

一次拖拽无论产生多少 `pointermove` 都只能新增一个撤销记录。没有产生有效变化时不得写入事务。

## 8. 模块边界

### 8.1 `pet-core`

- 定义直接操控能力、姿势卡契约和有限诊断。
- 提供屏幕/局部拖动输入到语义控制补丁的纯函数求解器。
- 复用现有控制范围、镜像规则、Two Bone IK/FABRIK 和阶段配方归一化。
- 不导入 Vue、Pinia、Three 或浏览器事件类型。

### 8.2 渲染适配器

- 在唯一 `CloudFoxStudioCanvas` 中注册语义拾取目标、部位高亮和拖拽辅助图形。
- 只通过稳定事件向页面报告选中部位、命中信息和操控坐标，不直接修改资产 Store。
- 不创建第二个 Canvas、Skeleton、RAF 或隐藏渲染循环。

### 8.3 编辑 Store

- 管理当前部位、移动/旋转模式、拖拽会话和单次事务。
- 将姿势卡、浮动工具、直接拖拽、语义滑杆和精确输入汇合为同一个 `updateSimpleStage` 数据流。
- 继续拥有撤销/重做、编译、保存状态和动作切换保护。

### 8.4 Vue 组件

- `StudioMotionDirectManipulator`：画布上的选中高亮、浮动工具和指针协调。
- `StudioMotionPartInspector`：固定部位属性栏和窄屏底部抽屉。
- `StudioMotionPoseCards`：按能力显示快速姿势。
- 现有 `StudioMotionTransformEditor` 保留给高级编辑；引导模式不再显示树形部位列表和密集数值行。

## 9. 错误处理与恢复

- 拾取不到可编辑部位时保持原选择或取消选择，不生成错误资产。
- 求解结果出现非有限值、缺失控制或损坏能力时阻止提交，恢复拖拽前预览，并显示“该部位暂时无法这样调整”。
- 不可达目标属于正常钳制状态，不作为错误；界面提示已到安全范围。
- 当前模型缺少可选部位时隐藏对应姿势卡和参数，不显示无效控制。
- 编译失败时保留拖拽前最后一个可播放资产，允许撤销或重试，不覆盖本地存储。
- 自动保存失败继续保留内存草稿和现有重试入口。

## 10. 兼容与迁移

- 不改变 `StudioMotionAssetV2`、阶段扩展 `yk-pets/simple-motion-authoring/v1` 或 v3 本地存储键。
- 直接操控最终写入现有阶段 `pose`，旧阶段动作无需迁移即可编辑。
- 没有阶段配方的旧动作继续进入高级编辑，不尝试逆向生成姿势卡或直接操控配方。
- 复杂模式入口继续隐藏；本轮只要求简单模式双足萌宠正式可用。
- 能力契约按语义部位设计，为未来人类、其他双足萌宠、四足动物和机甲保留扩展点，但不把尚未实现的 Profile 描述为已支持。

## 11. 可访问性与输入方式

- 所有可拾取部位必须有等价的键盘部位选择入口，不能只依赖鼠标命中。
- 移动/旋转使用具有 `aria-pressed` 的按钮组；浮动工具和属性栏共享可访问名称。
- 滑杆支持方向键和明确数值，精确输入具有中文标签、单位、最小值和最大值。
- 拖拽高亮、模式和钳制状态同时使用图形、文字和颜色表达。
- `prefers-reduced-motion` 下关闭非必要浮动和高亮动画，但不影响实时姿势更新。
- 触控使用指针捕获，操控柄具有稳定点击尺寸；画布空白拖动和部位拖动必须可预测地区分。

## 12. 测试与验收

### 12.1 领域测试

- 每个正式双足萌宠部位只暴露合法模式、控制和姿势卡。
- 同一拖拽输入产生确定、有限且不突变输入的控制补丁。
- 手脚目标在可达域内正确联动，在域外稳定钳制且不改变骨骼长度。
- 旋转遵守关节限制，精确输入不能绕过限制。
- 对称编辑镜像正确，不支持部位安全忽略。
- 损坏能力、异常输入和非有限坐标返回有界中文诊断。

### 12.2 Store 与组件测试

- 点击部位会同步浮动工具和固定属性栏。
- 姿势卡、直接拖拽、滑杆和精确输入更新同一阶段姿势。
- 一次拖拽只生成一个撤销记录；取消拖拽不产生修改。
- 切换阶段或动作时不会遗留指针捕获或临时预览。
- 高级编辑继续使用原 `StudioMotionTransformEditor`，切换模式不改变播放结果。

### 12.3 浏览器验收

- 1440×900：逐一选择头部、身体、左右手脚、耳朵和尾巴，验证悬停、选中、移动、旋转、姿势卡、参数同步、对称、复位、撤销/重做和自动保存。
- 验证手臂肩膀始终连接，腿脚无断层，拖到不可达位置出现安全提示且不穿插崩坏。
- 验证画布空白拖动旋转视角、部位拖动编辑姿势，两者不争抢指针。
- 760×900：属性栏成为底部抽屉，浮动工具不出界，阶段条可滚动，页面无横向溢出。
- 刷新后选定动作和阶段姿势保持；控制台无 error、hydration mismatch 或重复 Canvas。

## 13. 第一阶段交付边界

第一阶段必须交付：

- 简单模式双足萌宠语义部位拾取；
- 移动/旋转浮动工具；
- 手脚末端安全移动、常用部位安全旋转；
- 固定部位属性栏和窄屏底部抽屉；
- 头部、身体、手、脚、耳朵和尾巴的基础姿势卡；
- 语义参数与精确参数双向同步；
- 单次拖拽事务、撤销/重做和自动保存；
- 单 Canvas 双视口浏览器验收。

第一阶段不包含：

- 专业三轴 Gizmo、任意多选或骨骼层级编辑；
- 自动动作捕捉、视频姿态识别或真实物理仿真；
- 人类、四足动物和机甲的正式 Profile；
- 复杂模式恢复、高细节蒙皮或 DCC 格式导出；
- 将保守的 IK、平衡和接触规则描述为真实人体动力学。

这些边界不妨碍后续扩展，但不得为未来能力提前增加简单模式的操作负担。
