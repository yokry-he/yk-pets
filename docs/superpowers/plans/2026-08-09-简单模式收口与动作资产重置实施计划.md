# 简单模式收口与动作资产重置实施计划

> **面向自动化开发者：** 必须使用 `executing-plans` 按任务逐项实施；每一步使用复选框跟踪。

**目标：** 隐藏 Studio 模型模式切换入口，并通过一次性 v2→v3 迁移清除所有浏览器中的旧自定义动作，同时保留道具与内置资产。

**架构：** Studio 布局使用固定关闭的显示门禁保留可恢复接线；资产 Store 通过版本化存储迁移区分“历史数据首次升级”和“v3 正常水合”，只在前者丢弃动作。动作工坊在水合后修复失效的选中动作引用。

**技术栈：** Vue 3、Nuxt 4、Pinia、TypeScript、Node.js `assert`、静态结构门禁。

### 任务二：实施入口隐藏和一次性迁移

**文件：**

- 修改：`apps/playground/app/layouts/studio.vue`
- 修改：`apps/playground/app/domain/studio-workspace.ts`
- 修改：`apps/playground/app/stores/studio-assets.ts`
- 修改：`apps/playground/app/pages/studio/motion.vue`

- [x] **步骤一：隐藏模型模式切换入口**

在布局声明 `const modelModeSwitchVisible = false`，并给 `StudioModelModeSwitch` 增加 `v-if="modelModeSwitchVisible"`；不删除组件、事件处理或复杂模型逻辑。

- [x] **步骤二：升级资产存储键**

声明 v3 当前键、v2 历史键与 v1 历史键，避免把 v2 继续当成当前格式。

- [x] **步骤三：实现纯迁移归一化函数**

在无 Nuxt 运行时依赖的 `studio-workspace.ts` 中导出 `normalizeStudioAssetHydration(input, { resetLegacyMotions })`，统一规范化道具；仅在迁移历史数据时返回空动作，正常 v3 水合保留动作。Pinia Store 只负责读取、写入和删除存储键。

- [x] **步骤四：接入一次性迁移**

水合时优先读取 v3；只有 v3 不存在时读取 v2/v1 并清空动作。成功迁移后写入 v3，再移除 v2/v1 历史键。

- [x] **步骤五：清理失效选择**

动作工坊完成资产和会话水合后，如果 `selectedMotionId` 不存在于迁移后的动作列表，则调用 `session.selectMotion('')`。

## 实施结果

- 根因：前一次只记录了隐藏入口的设计方案，未修改生产布局；同时，自定义动作保存在各浏览器独立的 `localStorage` 中，不能通过另一浏览器会话直接清理。
- RED 验证：三项定向门禁分别因缺少显示门禁、`normalizeStudioAssetHydration` 和 v3 迁移契约而失败。
- GREEN 验证：模型模式、内置资产、语义动作、Studio 工作区与道具编辑门禁均通过；Playground 类型检查、构建及根目录全量类型检查均为 exit 0。构建仅保留既有 sourcemap、VueUse `PURE` 注释位置和大 chunk 警告。
- 浏览器验收：`/studio/library` 与 `/studio/motion` 均不再渲染模式切换入口，旧自定义动作计数为 0，五个基础动作模板与六个内置道具保留，控制台无错误或警告。
