# 表情与动态动作扩展设计

## 1. 目标

本批次把动作工坊从单纯的姿态编辑器扩展为能够编排姿态、表情、安全形变和道具事件的动画工作台，同时保持外观资产与动作资产解耦。

成功标准：

- 外观工坊提供更多可辨识的眼睛与鼻子造型；
- 动作工坊能够在当前播放头写入身体部位的动作安全参数；
- 动作停止后，所有动态形变都恢复到当前外观配方定义的基础值；
- 内置动作覆盖舞蹈、功夫和灵动运动，并可携带内置道具；
- 旧外观、旧动作和旧道具继续通过规范化流程加载；
- Studio 与正式 Cloud Fox 渲染器继续使用同一套语义 Rig 和单一模型拓扑。

## 2. 现状与问题

当前语义 Rig 已支持根节点、身体、头部、前后爪、耳朵、尾巴、触角的位移、旋转或局部比例，并支持左右眼闭合、视线与嘴部开合。动作工坊也已经具备当前帧、已选关键帧和整段动作三种编辑范围。

现有不足是：

- 眼睛和鼻子的静态样式数量有限，情绪辨识主要依赖闭眼和嘴部；
- 眼睛比例、眼距、瞳孔、鼻部形变、耳朵张合、尾巴蓬松等外观相关参数还不能安全地进入动作轨道；
- 内置动作主要来自扩展行为列表，缺少可直接复用的 Studio 动作模板；
- 道具工坊只有用户自建资产，没有稳定、只读、可复制的内置道具目录；
- 动作与内置道具之间没有开箱即用的组合模板。

## 3. 核心设计

### 3.1 基础外观与动作叠加

外观工坊继续保存宠物的基础外观。动作关键帧只保存语义通道值，不复制整份外观 JSON。

渲染顺序为：

1. 规范化基础外观；
2. 计算当前时间的语义姿态；
3. 将动作安全形变作为相对值叠加到基础外观；
4. 计算表情和离散样式覆盖；
5. 计算道具挂载与事件状态；
6. 交给统一 Cloud Fox 渲染器输出。

这样可以避免动作永久修改外观，也能让同一个动作应用到不同体型的宠物。

### 3.2 动作安全参数白名单

第一批允许逐帧编辑的安全参数包括：

- 身体：X/Y/Z 比例；
- 头部：统一比例；
- 眼睛：统一比例、眼距、左右闭合、视线 X/Y、瞳孔比例、表情倾斜；
- 鼻子：X/Y/Z 比例、上下偏移、嗅闻抖动、发光强度；
- 嘴部：开合和表情曲线；
- 耳朵：左右张合与现有三轴旋转；
- 前爪：长度与爪尖弯曲；
- 尾巴：根部/中段/尾尖旋转、整体长度和蓬松比例；
- 触角：长度、旋转和发光强度。

连续参数采用数值关键帧与现有线性、平滑、贝塞尔插值。眼睛或鼻子样式属于离散参数，不写入连续语义 Rig；首批内置动作通过连续形变表达情绪，避免形状在相邻帧之间错误插值。

不进入白名单的参数包括物种、模型拓扑、身体/头部基础类型、尾巴段数、材质结构和本地 GLB。这些参数只能在外观或道具工坊中修改。

### 3.3 表情造型

第一批新增眼睛：开心弯月眼、生气锐角眼、委屈下垂眼、惊讶圆睁眼、爱心眼、眩晕旋涡眼。

第一批新增鼻子：猫系鼻、水晶鼻、星光鼻。鼻子的嗅闻、缩放和发光由动作语义通道控制，不把动态状态伪装成新的静态样式。

所有新造型必须：

- 使用现有参数化几何和材质系统；
- 支持不同头型、眼距和眼睛比例；
- 保持闭眼、视线和动作表情通道兼容；
- 通过外观规范化、随机生成和导入导出流程。

### 3.4 动作工坊交互

动作部件树增加“鼻子”，并将“眼睛与嘴部”调整为更明确的表情分组。用户选择部位和模式后，可以在当前播放头写入安全参数。

仍沿用三种范围：

- 当前帧：在播放头位置创建或替换关键帧；
- 已选关键帧：批量调整所选值；
- 整段动作：只用于已有的整体修正能力，不允许修改离散样式。

自动关键帧继续决定输入时是否立即写入。数值输入、加减按钮、拖拽控制与高级通道编辑器必须使用同一个动作编辑命令，避免形成多套状态。

### 3.5 内置动作与道具

新增只读的 Studio 内置资产注册表。内置资产使用稳定 ID，不写入用户本地存储；用户可以复制为自定义资产后继续编辑。

首批内置道具：

- 星云长棍；
- 能量剑；
- 星光折扇；
- 双荧光棒；
- 飘带；
- 能量球。

首批内置动作模板：

- 舞蹈：元气踏步舞、星光摆胯舞；
- 功夫：马步冲拳、星云棍花；
- 灵动运动：侧手翻、冲刺急停。

其中星云棍花默认使用星云长棍，星光摆胯舞默认使用双荧光棒。动作模板包含身体重心、四肢、头部、耳尾延迟、表情通道和必要的道具事件，不只旋转根节点。

## 4. 数据与兼容性

- 语义 Rig 保持版本化；新增通道对旧动作表现为中性值；
- 动作资产仍保存数值轨道，旧 `schemaVersion: 2` 数据可直接规范化；
- 内置动作和道具使用独立注册表，不污染用户资产存储；
- 用户复制内置资产时生成新的本地 ID 和时间戳；
- 未识别的旧通道继续按当前诊断策略丢弃，不产生运行时异常；
- 新眼睛与鼻子 ID 纳入外观规范化集合，旧外观维持原选择。

## 5. 错误与边界处理

- 所有动态形变值必须在 Rig 定义的范围内钳制；
- 比例不得接近零或变为负数；
- 内置动作引用缺失道具时仍播放姿态，并输出可见诊断；
- 道具事件时间钳制在动作时长内；
- 离散样式不允许使用平滑插值；
- 不兼容眼型的视线覆盖应安全退化，不影响眼睛主体渲染。

## 6. 验证

- 单元测试覆盖新通道中性值、范围、插值、旧动作兼容和动作恢复；
- 契约检查覆盖新眼鼻选项、部件树、安全控制和内置资产注册；
- 每个内置动作验证关键帧数量、通道合法性、时长及道具引用；
- 构建与类型检查覆盖 Playground、pet-core 和扩展；
- 浏览器验收覆盖正面/侧面、新眼鼻切换、逐帧写入、播放恢复、道具挂载、窄屏溢出和 WebGL 控制台错误。

## 7. 实施顺序与回滚

1. 先扩展 Rig 与回归测试；
2. 接入统一渲染器和外观选项；
3. 接入动作工坊安全参数编辑；
4. 增加内置道具及动作模板；
5. 同步资产库、文档和浏览器验收。

每一层均保持旧数据可读取。若某个新造型或模板存在渲染问题，可从注册表移除对应条目而不迁移或删除用户数据；新增 Rig 通道回到中性值即可恢复旧表现。
