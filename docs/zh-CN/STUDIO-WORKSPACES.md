# 统一 Studio 工作区架构

## 产品结构

YK-PETS Studio 使用同一个产品壳，但将不同创作任务拆成独立路由：

- `/studio/appearance`：外观工坊；
- `/studio/motion`：动作工坊；
- `/studio/props`：道具工坊；
- `/studio/library`：共享资产库。

旧入口 `/studio` 只负责兼容跳转到外观工坊。四个工作区共享产品导航和当前上下文，但不共享各编辑器内部的撤销栈。

## 共享上下文

`StudioSession` 持久化以下选择：

- 当前外观资产 ID；
- 当前动作资产 ID；
- 当前道具资产 ID；
- 预览视角；
- 预览背景；
- 最近使用的工作区。

这些信息只保存在浏览器本机。刷新页面或在工作区间跳转时，当前资产选择不会丢失。

## 资产边界

外观、动作和道具是三类独立资产：

- 外观描述宠物的基础结构、颜色和静态默认姿态；
- 动作描述相对姿态、总时长、循环方式和道具依赖；
- 道具描述资产类型、默认挂载点和内部锚点。

动作引用道具 ID，不直接修改道具定义。道具工坊可跳转到动作工坊进行测试，动作工坊也可以跳转到道具定义。

## 当前基础批次

本批次已经完成：

- 统一 Studio 顶层导航；
- 四个独立路由；
- 本地会话 Store；
- 动作和道具资产元数据 Store；
- 动作创建、命名、总时长和循环方式；
- 道具创建、类型、默认挂载点和内部锚点；
- 资产库中的查看、编辑跳转和删除；
- 现有完整外观工坊无损迁移；
- `/studio` 历史链接兼容。

## 尚未完成

动作工坊目前只建立资产和时间轴基础结构，尚未实现关键帧写入、轨道插值、曲线编辑和道具事件。道具工坊目前只建立资产、挂载和组件层级基础，尚未实现可编辑几何、材质和抓握点操纵器。

后续实现必须继续复用唯一正式 Cloud Fox 渲染器，不能为动作或道具复制第二套宠物拓扑。

## 安全边界

本批次未新增：

- Chrome 权限；
- 网络上传；
- 后台轮询；
- WebSocket；
- 宿主网页持久配置 DOM；
- 第二个长期运行的 WebGL 场景。
