# 开发与运行指南

## 1. 环境要求

- Node.js 22 或更高版本；
- Corepack；
- pnpm 11.13.1；
- Chrome 或 Edge，支持 Manifest V3 Side Panel；
- 运行 3D 页面时需要可用的 WebGL 环境。

技术选型和依赖职责见[技术栈详解](./技术栈.md)，模块边界见[技术架构](./技术架构.md)。

## 2. 安装

```bash
corepack enable
pnpm install --frozen-lockfile
```

必须使用根目录 `pnpm-lock.yaml` 对应的 pnpm，不要在 Workspace 内单独使用 npm 或 yarn 安装依赖。

## 3. 启动开发环境

### Playground 与 Pet Studio

```bash
pnpm dev:playground
```

常用入口：

```text
http://localhost:3000/audit-lab
http://localhost:3000/studio/appearance
http://localhost:3000/studio/motion
http://localhost:3000/studio/props
http://localhost:3000/studio/library
```

### Local Agent

```bash
pnpm dev:agent
```

根脚本默认以 `apps/playground` 作为 Agent 项目根目录。直接使用 CLI 时可以指定其他项目：

```bash
yk-pets-agent dev --root /absolute/path/to/project
```

连接地址和 Token 只用于本机开发，不要写入文档、提交或日志样例。

### 浏览器扩展

```bash
pnpm dev:extension
```

在 `chrome://extensions` 开启开发者模式并加载：

```text
apps/extension/.output/chrome-mv3
```

扩展安装或重新构建后，需要重载扩展并刷新目标 HTTP/HTTPS 标签页，旧页面不会自动获得最新 Content Script。

## 4. 推荐联调顺序

1. 启动 Playground；
2. 启动 Local Agent；
3. 启动扩展开发构建；
4. 加载或重载扩展；
5. 刷新 `/audit-lab`；
6. 在 Side Panel 连接终端显示的本机地址和 Token；
7. 依次验证审计、问题定位、DOM 预览、补丁生成、确认写入、检查和回滚。

只有查看 Studio 时，可以只启动 Playground。验证配方同步、扩展正式渲染器或 Side Panel 时，必须启动扩展并在真实浏览器操作。

## 5. 常见开发落点

| 修改类型 | 首选位置 | 同步检查 |
|---|---|---|
| 动作时间、插值、关键帧、道具事件 | `packages/pet-core/src/motion/` | 领域测试、动作契约、双语文档 |
| 道具实体和锚点 | `packages/pet-core/src/props/` | 道具测试、资源预算、迁移 |
| Studio 页面和状态 | `apps/playground/app/pages/studio/`、`stores/` | 路由、持久化、响应式和 WebGL |
| 正式云狐视觉 | `ExtensionAlignedCloudFox.vue` 及薄语义组件 | 唯一渲染器门禁、视觉案例、扩展构建 |
| 扩展消息和共享数据 | `packages/shared/src/` | Schema、兼容别名、三端消费者 |
| 页面审计与 Overlay | `apps/extension/entrypoints/content*` | Shadow DOM、宿主页面污染、键盘交互 |
| Network Lab | `apps/extension/features/network-lab/` | Domain 到 Presentation 全链路 |
| Local Agent | `packages/local-agent/src/` | 路径限制、哈希、白名单命令、Vitest |
| 技术栈或依赖 | 各 `package.json` 和锁文件 | 技术栈、架构、开发和发布文档 |

## 6. 开发约束

- 先修改领域模型和纯逻辑，再接应用层、平台适配器和 UI；
- 不创建第二套正式云狐拓扑或长期运行的第二个 TresCanvas；
- 外观、动作和道具资产保持独立，动作不得改写外观配方；
- Domain 不依赖 Vue、Chrome API、DOM 或文件系统；
- 新持久化格式必须有版本、规范化和迁移策略；
- 用户可见文案默认使用中文，工程注释使用中英双语；
- 新增扩展权限、生产依赖、公共 API 或破坏性迁移前先完成方案评审。

## 7. 验证矩阵

### 文档或注释

```bash
pnpm check:documentation
pnpm check:brand
```

### 领域逻辑

```bash
pnpm --filter @yk-pets/pet-core test
pnpm test
pnpm typecheck
```

### Local Agent

```bash
pnpm --filter @nova/local-agent test
pnpm --filter @nova/local-agent typecheck
pnpm build:agent
```

### 扩展

```bash
pnpm build:extension
pnpm typecheck
```

随后在真实 Chrome 验证 Content Script、Side Panel、权限、宿主网页样式和窄视口。

### Playground 与 Studio

```bash
pnpm --filter @nova/playground typecheck
pnpm build:playground
pnpm test
```

涉及 3D、布局、拖拽、滚轮、键盘、音频或本地 GLB 时，还需要真实浏览器人工验收。

### 完整交付门禁

```bash
pnpm typecheck
pnpm test
pnpm build
pnpm build:playground
```

`pnpm typecheck` 包含大量架构和历史回归脚本，耗时和失败信息都比单个 Workspace 类型检查更广。

## 8. 文档和 AI 交接

修改 `apps/` 或 `packages/` 的功能源码时，同一功能批次必须更新 `.ai/project-state.json` 和至少一项交接上下文。中文文档位于 `docs/zh-CN/` 并使用中文文件名，英文文档位于 `docs/en/`。

修改文档链接后运行 `pnpm check:documentation`，该门禁会校验中英文文档配对、关键章节、中文文件名和仓库内 Markdown 相对链接。

## 9. 构建产物

```bash
pnpm zip:extension
pnpm build:agent
pnpm build:playground
```

- 扩展目录和 ZIP：`apps/extension/.output/`；
- Local Agent：`packages/local-agent/dist/`；
- Nuxt：`apps/playground/.output/`。

构建产物不应手工编辑或提交，发布流程见[构建、打包与发布](./构建打包与发布.md)。

## 10. 故障定位顺序

1. 检查工作区状态、Node/pnpm 版本和锁文件；
2. 检查是否存在旧开发进程、HMR 缓存或未重载扩展；
3. 从失败的最小 Workspace 检查开始；
4. 再运行根级专项门禁和完整类型检查；
5. 浏览器问题检查 Console、扩展 Service Worker 和 Side Panel；
6. CSS 异常先排查全局选择器和宿主页面污染；
7. WebSocket 问题核对监听地址、Token、Origin 和 Agent 根目录。

更多案例见[故障排查](./故障排查.md)。
