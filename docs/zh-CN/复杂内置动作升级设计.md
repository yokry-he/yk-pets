# 复杂内置动作升级设计

## 背景与根因

现有 6 个内置动作持续时间仅为 1.9–3.2 秒，大多数通道采用等间隔左右往复。动作虽然能够播放，但缺少预备、蓄力、重心转移、速度变化、高潮和收势，因此更像控制器演示而不是完整编排。

当前云狐是程序化节点模型，已经具备根节点、身体、头部、前后爪、爪尖、耳朵、眼睛、口鼻、尾巴和触角通道，但没有真人骨骼中的脊柱分节、肩肘腕、髋膝踝和足底接触约束。因此本轮目标是提升卡通动作的节奏、层次和整体协调，不承诺真人动作捕捉级还原。

## 参考依据

- [WDSF 评分体系](https://www.worlddancesport.org/About/Competition/Declaring-The-Winners)将舞蹈拆为技术质量、音乐性、配合能力、编排与呈现。本项目据此强化节拍重音、动作短语和姿态对比。
- [国际武联套路说明](https://iwuf.org/en/sport-wushu/competitive-wushu/taolu/)强调手法、步法、跳跃、平衡及连续技术组合。
- [国际武联套路裁判摘要](https://www.iwuf.org/wp-content/uploads/2020/03/IWUF-Wushu-Taolu-Competition-Rules-Judging-Methods-Excerpt-2019.pdf)强调眼、手、身法、步法及器械协调、发力点和鲜明节奏。
- [冲刺加速阶段研究](https://pubmed.ncbi.nlm.nih.gov/24996923/)表明启动、加速中段和后段具有不同姿态策略；[减速研究](https://pubmed.ncbi.nlm.nih.gov/33217086/)显示制动阶段需要更长支撑时间和更强制动表现。本项目据此将冲刺拆为启动、加速、巡航、制动、回稳。
- [Blender F-Curve 文档](https://docs.blender.org/manual/en/4.2/editors/graph_editor/fcurves/introduction.html)说明关键帧之间应由曲线插值构成连续变化。本项目继续使用语义轨道，但增加非均匀关键帧和分段节奏。

## 方案选择

### 方案 A：只增加关键帧

直接延长现有数组并增加采样点，改动最少，但六个动作会继续复制大量重复数据，后续很难统一调整节拍和动作阶段。

### 方案 B：动作短语构建层（采用）

在内置动作模块中加入轻量的关键帧短语工具：归一化时间点、轨道合并、首尾稳定和重复节拍。每个动作仍输出当前 `StudioMotionAssetV2`，不改变持久化协议和编辑器，却能用明确阶段组织更长、更复杂的编排。

### 方案 C：外部骨骼动画或动作捕捉

能够获得最高真人还原度，但当前程序化云狐没有兼容的人形骨骼、蒙皮权重和动作重定向链路，需要新增 GLB 骨骼模型、IK、足底锁定和重定向系统，超出本轮范围。

## 动作编排

### 元气踏步舞

- 时长：8 秒，循环。
- 结构：准备弹跳 → 左右踏步 → 交叉摆臂 → 半转身 → 双拍高潮 → 回到循环起点。
- 特征：8 拍节奏、头身反向、脚步和手臂错拍、眨眼与笑脸重音。

### 星光摆胯舞

- 时长：10 秒，循环。
- 结构：荧光棒亮相 → 摆胯波浪 → 上举交叉 → 旋转换边 → 连续闪光 → 回位。
- 特征：双手非镜像、身体横摆与根节点纵向弹跳错相，发光变化跟随重拍。

### 马步组合拳

- 时长：8.4 秒，单次。
- 结构：抱拳预备 → 下沉马步 → 左冲拳 → 右冲拳 → 格挡反击 → 蓄力重拳 → 收势。
- 特征：拳到、眼到、身体扭转到，出拳前有回拉，击中后有短暂停顿和回弹。

### 星云棍术组合

- 时长：12 秒，单次。
- 结构：持棍亮相 → 右侧立圆棍花 → 背后换手 → 横扫转身 → 跳步下劈 → 架棍收势。
- 特征：器械事件贯穿整段，道具发光在横扫和下劈时增强，视线跟随棍势而不是机械左右摆动。

### 灵巧体操组合

- 时长：8.8 秒，单次。
- 结构：助跑两步 → 侧手翻 → 落地反弹 → 团身跳转 → 单脚平衡 → 鞠躬收势。
- 特征：空中阶段拉长，起跳前压低重心，落地后有压缩和恢复，尾巴承担反向平衡。

### 冲刺急停挑战

- 时长：9.2 秒，单次。
- 结构：起跑预备 → 三段加速 → 高速巡航 → 提前制动 → 侧身急停 → 回头确认 → 放松回位。
- 特征：步频随阶段变化，身体前倾逐步减小，急停时重心后移、前爪张开、耳尾因惯性滞后。

## 数据与实现边界

- 保持 `StudioMotionAssetV2`、现有语义 Rig 和资产复制流程不变。
- 每个动作至少包含 5 个动作阶段、10 个参与通道和 45 个关键帧。
- 循环动作首尾姿态严格一致；单次动作必须包含明确准备与收势。
- 关键帧不采用统一时间间隔：发力点更密，保持段更疏。
- 道具动作必须包含创建、挂载、强调样式和销毁事件；样式事件与动作高潮对齐。
- 不新增生产依赖，不导入第三方动作文件，不复制受版权保护的具体编舞。

## 验证标准

- 契约测试检查全部动作时长、阶段数、通道数、关键帧数和首尾规则。
- 资产测试继续验证通道合法、时间范围、ID 唯一和道具依赖完整。
- 浏览器逐个播放 6 个动作，检查动作持续时间、道具事件、无运行时错误和窄屏布局。
- 生产构建、类型检查和现有测试必须全部通过。

## 后续需要用户协助的条件

本轮不需要额外输入。若后续目标升级为真人舞蹈或武术动作的高保真复刻，需要以下任一素材：

- 带蒙皮和完整骨骼命名的云狐 GLB；或
- 正面与侧面的动作参考视频，并允许据此人工拆帧；或
- BVH/FBX 动作捕捉文件及其使用授权。

届时还需要新增动作重定向、IK、足底接触和骨骼约束，不应继续用根节点与爪部旋转模拟。
