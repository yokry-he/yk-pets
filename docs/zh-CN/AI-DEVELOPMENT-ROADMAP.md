# AI 开发路线图

本路线图用于下一会话恢复开发顺序，不替代 GitHub 实时状态。每个阶段的功能提交必须同步更新 AI 交接包并通过完整 CI。

## 阶段 A：语义 Rig 与关键帧领域

- 状态：领域实现完成，等待完整 CI 和浏览器迁移人工验收
- 目标：建立与具体 Three.js Mesh 解耦的动作数据层。

已完成：

- 定义宠物根节点、身体、头部、前后爪、耳朵、眼睛、嘴巴、尾巴和触角的稳定语义通道；
- 以毫秒保存时间，FPS 仅作为显示和吸附网格元数据；
- 定义 schema v2 动作、轨道、关键帧、循环和规范化；
- 姿态保存为相对于外观默认挂点和尺寸的偏移；
- 重复轨道合并、关键帧排序、重复时间最后写入获胜和范围裁剪；
- `step` 与 `linear` 插值；
- `once`、`loop`、`ping-pong` 时间求值；
- 无 UI 的完整语义姿态求值器；
- v1 到 v2 本地资产迁移；
- 确定性领域测试和架构门禁。

完成标准：能够在无 UI 条件下创建动作资产、插入关键帧并在任意时间求值完整姿态。该标准已由领域测试覆盖。

仍需人工确认：真实浏览器中旧 v1 本地数据迁移、刷新恢复和回滚。

## 阶段 B：时间轴编辑与正式预览

- 状态：Next

建议顺序：

1. 建立动作编辑草稿和独立撤销/重做；
2. 添加播放指针和基础播放控制；
3. 添加、删除、复制、移动和多选关键帧；
4. 使用领域规范化器处理重复时间、范围和总时长变化；
5. 将每帧一次求值的 `EvaluatedCloudFoxPose` 传入唯一正式预览；
6. 为根节点、身体、头部、前后爪、耳朵、眼嘴、尾巴和触角建立语义适配器；
7. 定义未写入通道继续保留呼吸、眨眼和视线，已写入通道按语义覆盖或加成；
8. 完成保存、刷新恢复和无道具自定义动作播放。

本阶段只使用 `step` 与 `linear`。平滑、贝塞尔和曲线编辑器留到高级阶段。

完成标准：用户能制作、保存、刷新恢复并播放不含道具事件的完整自定义动作，且不复制渲染器或新增长期 WebGL 场景。

## 阶段 C：道具事件轨道

- 动作引用稳定道具 ID；
- 创建、显示、挂载、分离、移动、隐藏和销毁事件；
- 世界坐标和宠物挂点之间转换；
- 颜色、尺寸、发光和粒子事件；
- 缺失依赖和删除清理。

完成标准：可制作确定性的持物、抛出、接住和效果道具动作。

## 阶段 D：道具工坊实体编辑

- 参数化基础几何组合；
- 层级树与局部变换；
- 材质、颜色、透明度、金属度、粗糙度和发光；
- `origin`、`grip`、`display`、`emitter` 操纵器；
- 道具预览、复制、导入导出和资源预算。

完成标准：用户能创建不依赖远程资源的本地参数化道具，并在动作中稳定引用。

## 阶段 E：高级动画工具

- 平滑与贝塞尔插值；
- 曲线编辑器；
- 洋葱皮；
- 运动轨迹；
- 左右镜像与姿态预设；
- 动作分层和可中断策略；
- 可选 IK 辅助；
- 音效轨道；
- 经安全和性能评估后的本地 GLB 道具导入。

## 每阶段强制流程

1. 修改前核对 AI 包、代码、PR 和最新 CI；
2. 明确范围和验收标准；
3. 功能代码与 AI 包在同一提交；
4. 更新测试和架构门禁；
5. 运行完整 CI；
6. 全绿后更新 PR；
7. 保留真实浏览器和 WebGL 人工验收边界；
8. 未经明确要求不合并。
