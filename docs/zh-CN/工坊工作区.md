# 统一 Studio 工作区

YK-PETS Studio 使用同一个产品壳与四个路由：`/studio/appearance`、`/studio/motion`、`/studio/props`、`/studio/library`；`/studio` 仅作兼容跳转。外观、动作、道具三个工坊共享本地会话中的模型模式、视角与预览变换，撤销栈和资产身份仍各自独立。

## 启动与进入方式

```bash
corepack pnpm dev:playground
```

打开任一 `/studio/*` 路由即可进入对应工坊。首次将顶部模型模式切到“复杂”时，系统会为当前宠物创建本地、非破坏性的复杂模型草稿；不会覆盖简单模型、外观配方或已有动作/道具。复杂模型数据保存在浏览器本地的 `yk-pets:studio:model-variants:v1`，清除站点数据前应先导出需要保留的 Studio 数据。

## 已交付：双足萌宠第一阶段

- `biped-pet/v1` 是第一版正式 Rig Profile：站内程序化生成根、骨盆、脊柱、头部、左右肢体，以及可选耳朵、尾巴、触角链；人类、四足、机甲 Profile 只保留为未来契约，不是当前可选运行时模型。
- `CharacterModelRecipeV1` 是站内生成器输入，包含体型、比例、附属物与材质；归一化会修复未知枚举、非法数值和颜色，避免本地损坏草稿阻塞工坊。
- 编译器以确定顺序产出程序化骨架和网格，每个顶点最多四个自动生成的骨骼权重；它不需要 GLB、Blender 或手工绑定/手工蒙皮。
- `ComplexBipedPetRenderer` 将已就绪的编译结果转换为 Three `SkinnedMesh`、`Bone`、`Skeleton` 与 Socket，并在既有的唯一 `TresCanvas` 内使用；不会创建第二个长期 WebGL 场景。
- 外观、动作、道具三个工坊都读取同一宠物的持久化复杂配方；只有外观工坊可编辑配方并提交编译摘要，资产库展示实际配方、编译状态和诊断。
- 新手编辑器提供柔软、运动、圆润、纤细四个体型模板、九项安全比例，以及耳朵/尾巴/触角开关。滑块拖动期间只更新本地值，松开后才提交一次；键盘焦点、`aria-pressed`、稳定标签和 760px 单列布局均已接线。

## 已交付：Root Motion 与运动特效

- 复杂动作预览把 Root Motion、重心修正、混合 IK 和确定性 VFX 串入同一个 renderer 生命周期。容器整体位置与转向只有一个写入者，VFX 作为角色 primitive 的同级对象挂在现有 `TresCanvas`，不会创建第二个 Canvas、Skeleton 或 RAF。
- 动作工坊的“基础”页提供新手 Root Motion 设置：原地/实际移动、自动特效、预计距离/转向/跳高和恢复推荐值。系统会根据角色身高、接触、速度与动作来源自动换算，用户不需要编辑骨骼、曲线或粒子底层参数。
- 时间轴和道具事件继续读取循环内播放头；复杂 runtime 使用单调请求时间，保证行走跨多个循环连续前进、ping-pong 反向不误清状态、暂停冻结且恢复后接续。停止、用户回拖、动作切换或失败回退会集中清理位移、IK 锚点和旧粒子。
- 行走循环、冲刺急停挑战、起跳与落地提供实际移动语义；待机、招手、直拳及未声明 Root Motion 的旧动作安全保持原地。自动特效当前覆盖落地环、落地尘点、速度拖尾和急停火花。
- VFX 固定使用 `8/24/8/24` 四类槽位，总数 `64`；单次 burst 最多 `16`、拖尾最多 `8`、寿命最多 `1200ms`。该预算由运行时强制执行，反复播放不会无限创建 GPU 对象。
- 2026-07-29 Chromium 双视口功能验收确认：1440×900 下行走跨两个周期、冲刺制动、跳跃、暂停/停止/回拖和模式互斥正常；760×900 修复后 708px 设置面板中的移动方式与预计结果实际成为单列。两个视口均为单 Canvas、无横向溢出、console error 与 hydration mismatch 为 0。冲刺 VFX 的 304 个信号由运行时探针确认，截图粒子较细微，不作为最终像素通过证据。

## 操作与数据流

1. 在外观工坊选择“复杂”模式，系统建立或读取当前 `petId` 的 `CharacterModelRecipeV1`。
2. 选择模板、修改比例或开关附属物；父层通过原子 patch 写入 Store，保留未修改字段，并清除旧编译摘要。
3. Store 与 Canvas 归一化同一份配方，框架无关编译器生成 `biped-pet/v1` 骨骼、网格和四权重数据。
4. Three 适配器在唯一 Canvas 内生成复杂预览；外观工坊只接受与当前配方哈希一致的 `ready` 结果并持久化摘要。
5. 动作、道具和资产库按相同 `petId` 读取该配方与状态。动作工坊会把既有云狐语义 Rig 编译为 `biped-pet/v1` 的 Quaternion Clip，并由复杂模型控制器按当前时间和权重采样。
6. ready 编译结果携带左右腿混合 IK 定义；控制器按“绑定姿态恢复 → FK → Root Motion → 重心 → 矩阵更新 → IK”执行，按肢体自动选择解析式 Two Bone IK 或受约束 FABRIK，并把确定性 VFX 信号交给同场景有界对象池。

`CharacterModelRecipeV1 -> normalizeBipedPetModelRecipe -> compileBipedPetCharacter -> ComplexBipedPetRenderer -> CloudFoxStudioCanvas -> complex-compiled -> studio-model-variants.commitComplexCompilation`

## 失败与回退

- 配方或持久化摘要损坏时，归一化会恢复可安全编辑的草稿，不抛出到界面。
- 运行时编译结果被阻塞、哈希陈旧或 Three 创建失败时，Canvas 显示“生成失败，已回退简单模型”，并在当前会话实际渲染原有简单模型；用户保存的复杂模式选择和配方不会被删除。
- 简单模式、无复杂配方和所有回退路径均继续沿用唯一的正式简单云狐渲染链路，不会与复杂模型叠加。

## 当前限制（尚未完成）

- 已完成的是骨架/网格/四权重的程序化生成、Three 复杂预览、配方持久化与新手编辑；站内格式仅供本站 runtime，不承诺 DCC 导出，也不是 GLB 交换格式。
- 已完成 Profile 专属 Quaternion Clip、五个基础动作、复杂模型播放控制器和动作工坊一键模板入口；模板复制后可继续使用现有关键帧与身体部件工具编辑。
- 已完成复杂模型运行时混合 IK、足底锁定、Root Motion、同场景有界特效和正式 renderer 生命周期；尚未实现更高质量的复杂舞蹈/功夫/运动动作库、motion warping、命中和武器轨迹特效。
- 行走单支撑在部分采样点会超出纯旋转腿链可达域；当前 Root Motion/重心策略与五轮集成 IK 会在尺寸化预算内消化差值，超出时继续以有限 `clamped` 诊断回退且不拉长骨骼。
- 当前复杂模型使用第一阶段低细节程序化拓扑和自动权重，不能据此宣称已达到真实人物/动物动作的关节体积、重心、接触和最终画面质量。
- 人类、四足、机甲仅有 Profile 方向，不是已交付的模型或编辑器。
- 真实 GPU、WebGL 和跨浏览器最终验收仍是人工项目；当前自动测试与静态门禁不能替代该验收。

## 后续动作计划

1. 在现有 Root Motion、混合 IK、足底锁定与接触约束链路上扩展高级编舞、动作适配与 motion warping。
2. 改进程序化拓扑与自动权重，再扩展命中、武器轨迹等确定性动作特效。
3. 将人类、四足、机甲 Profile 从契约扩展为独立的生成与验证批次。
4. 保留本批已经完成的 1440×900、760×900、键盘、持久化与控制台功能复测记录；后续单独完成跨浏览器 GPU/WebGL 与最终像素验收，在完成前只保持图形验收项目为未完成。

## 安全边界

本阶段没有新增 Chrome 权限、网络上传、后台轮询、WebSocket 或宿主网页持久配置 DOM。模型配方、编译摘要和工坊会话均为本地数据。
