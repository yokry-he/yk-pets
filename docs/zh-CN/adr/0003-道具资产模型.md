# ADR 0003：道具资产、实例与锚点

- 状态：Accepted

## 背景

动作需要持有、抛出和触发道具，但动作中的临时变换不能污染道具的基础定义。任意远程模型导入还会引入权限、安全和性能风险。

## 决策

- 道具定义与动作中的道具实例分离；
- 动作通过稳定道具 ID 引用资产；
- 道具至少拥有 `origin`、`grip`、`display` 和 `emitter` 锚点；
- 动作可以改变实例的位置、旋转、尺寸、颜色、发光和挂载，但不能修改资产定义；
- 首版道具工坊使用参数化基础几何和本地材质；
- GLB 导入必须经过独立安全、资源预算和兼容性评审后再决定。

## 结果

同一道具可以在多个动作中复用，资产更新和动作实例事件保持清晰边界。删除道具时必须检查并清理动作依赖。

## 拒绝方案

- 在动作文件中复制完整道具定义；
- 动作直接修改道具资产；
- 首版开放任意远程模型或脚本；
- 不使用稳定锚点而依赖世界坐标猜测抓握位置。
