# ADR 0004：动作关键帧领域与确定性求值

- 状态：Accepted

## 背景

动作工坊已经拥有稳定资产 ID、毫秒总时长和循环元数据，但旧资产只保存元数据，正式三十动作仍由多个渲染组件按行为 ID 分散求值。若直接从时间轴写入 Three.js 节点路径、外观参数或固定帧数组，自定义动作将无法跨头型、身体比例和渲染重构复用。

## 决策

- 在 `@yk-pets/pet-core` 中建立框架无关的 `cloud-fox-semantic-rig/v1`；
- 语义通道覆盖根节点、身体、头部、前后爪、耳朵、眼睛、嘴部、尾巴和触角；
- 位移保存为相对于基础挂点和外观尺度的标准化局部偏移，旋转使用弧度，缩放保存相对比例偏移；
- 动作时间只以整数毫秒持久化，`displayFps` 只控制界面显示与吸附网格；
- 动作资产升级到 schema v2，包含 `rigId`、`displayFps`、轨道与关键帧；
- 同一通道的重复轨道在规范化时合并，同一毫秒的重复关键帧采用输入顺序最后一个获胜；
- 第一阶段只支持 `step` 和 `linear` 插值；
- 无 UI 求值器一次输出完整语义姿态和实际写入通道列表；
- `appearanceId` 迁移为仅用于追溯创作上下文的 `authoringAppearanceId`，不参与动作求值；
- v1 本地资产迁移到 `yk-pets:studio:assets:v2`，保留旧存储用于回滚；
- 本 ADR 不接入正式渲染器，不实现时间轴关键帧编辑、自动关键帧、道具事件或曲线编辑器。

## 结果

动作领域现在可以在无 Vue、TresJS、Three.js 和浏览器 UI 的条件下创建资产、插入关键帧、规范化并在任意时间求值。正式渲染器后续只需消费统一语义姿态，不需要理解存储格式或时间轴数据清理规则。

## 兼容与迁移

- 旧动作 ID、名称、总时长、循环方式、道具依赖和时间戳保持不变；
- 旧 `appearanceId` 只迁移为创作上下文，不形成运行时绑定；
- 空轨道动作求值为完整中性姿态，因此现有待机预览不发生视觉变化；
- 三十个内置动作保持只读且运行时不变。

## 拒绝方案

- 关键帧直接绑定 Three.js Mesh 或 Vue ref；
- 用 FPS 帧号替代毫秒存储；
- 用外观静态配置保存动作姿态；
- 同时保留多个相同时间关键帧并依赖对象遍历顺序；
- 在领域合同稳定前接入复杂时间轴或第二套渲染器。
