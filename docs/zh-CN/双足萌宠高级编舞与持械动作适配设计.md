# 双足萌宠高级编舞与持械动作适配设计

## 1. 背景与目标

当前复杂双足萌宠已经具备程序化骨架、蒙皮、Quaternion Clip、接触阶段、混合 IK、足底锁定、Root Motion 与同场景运动特效，但长编排动作仍以固定关键帧为主。不同体型播放同一套持械动作时，副手握点、步幅、转身半径和命中位置不会自动匹配；继续单纯增加关键帧只能改善单一模型，无法实现“新手复制动作即可得到可信结果”的产品目标。

本阶段以 12 秒“星云棍术组合”为第一个高质量纵向样板，交付可复用的动作阶段、Motion/Pose Warping、双手持械约束和武器轨迹特效能力。用户不需要理解骨骼绑定、蒙皮、IK、局部坐标或粒子阈值。

## 2. 成功标准

- 用户复制“星云棍术组合”后直接播放，即可看到亮相、棍花、换手、横扫、跳步、下劈和收势。
- 系统根据复杂双足模型的身高、臂长、腿长和道具尺寸自动生成适配计划。
- 右手稳定拥有长棍，左手在指定阶段平滑跟随副握点，不拉长骨骼。
- Root Motion、重心、副手约束和足底 IK 按固定所有权顺序协作，不互相覆盖。
- 棍影、能量弧、下劈火花与冲击环由动作提示窗口和实际轨迹共同驱动，暂停、回拖和重复播放保持确定性。
- 任一增强能力失败时只关闭对应增强，基础动作和复杂模型继续播放。
- 第一批同时形成可复用契约和运行时边界，后续舞蹈、组合拳与体操不需要复制棍术专属求解器。

## 3. 非目标

- 不导入 GLB、FBX、BVH 或动作捕捉资产。
- 不提供 DCC 软件格式导出，站内渲染仍是唯一交付目标。
- 不在本批实现通用真人动作生成器、动作匹配数据库或物理布料。
- 不在本批完成舞蹈、组合拳、体操适配，也不提前关闭 Safari、Firefox、多 GPU 或高细节拓扑验收边界。
- 不通过骨骼缩放、蒙皮变形或关闭关节限制伪造握持和命中。

## 4. 参考依据

- Unreal Engine Motion Warping 使用命名时间窗把 Root Motion 的位移与旋转对齐指定目标，并允许分别控制平移、旋转和目标朝向。本项目采用相同的“基准动作 + 有界时间窗 + 语义目标”思想，但实现为框架无关 TypeScript 契约，不引入引擎依赖：<https://dev.epicgames.com/documentation/en-us/unreal-engine/motion-warping-in-unreal-engine>
- Unreal Engine Pose Warping 将朝向和步幅适配作为 Root Motion 之上的姿态修正，减少为不同方向和速度制作重复动作的需要。本项目只实现双足萌宠当前动作所需的朝向、步幅和支撑修正：<https://dev.epicgames.com/documentation/en-us/unreal-engine/pose-warping-in-unreal-engine>
- Unity Animation Rigging 的 Two Bone IK 使用 Root、Mid、Tip、Target 与 Hint 表达末端目标和弯曲方向。本项目复用已有解析式 Two Bone IK/FABRIK 数学能力，但由站内 Rig Profile 和动作约束自动提供目标：<https://docs.unity3d.com/Packages/com.unity.animation.rigging@1.2/manual/constraints/TwoBoneIKConstraint.html>
- Three.js `SkinnedMesh` 由 Skeleton、skin index 和 skin weight 驱动。本项目继续使用现有程序化生成的 `SkinnedMesh`，不切换到外部加载模型：<https://threejs.org/docs/pages/SkinnedMesh.html>

## 5. 方案选择

### 5.1 纯关键帧增强

继续为每种体型手工调整动作，开发初期最快，但副手握点、步幅与命中位置会随模型比例失配，且后续每个新动作都需要重复调参，因此不采用。

### 5.2 全程序化动作生成

由目标和规则实时生成全部姿态，自动化程度最高，但舞蹈和武术的准备、重音、停顿、高潮与收势容易机械化，也会让运行时承担不必要的编排职责，因此不采用。

### 5.3 编排基准与程序适配混合方案（采用）

现有长编排关键帧负责表演意图；程序只在显式阶段和安全预算内修正整体位移、朝向、步幅、副手握持、支撑与特效。该方案同时保留编排感和跨体型适配能力，符合用户此前选择的混合路线。

## 6. 版本化数据契约

### 6.1 动作适配扩展

新增独立命名空间 `yk-pets/biped-motion-adaptation/v1`，不修改 `StudioMotionAssetV2` 的基础字段，也不改变现有 `yk-pets/biped-motion/v1` 的 Root Motion、contacts、events 和来源语义。

扩展包含：

- `phases`：稳定 ID、开始/结束时间、阶段角色和强度；阶段角色限定为 `prepare`、`spin`、`handoff`、`sweep`、`takeoff`、`impact`、`recover`。
- `warpWindows`：开始/结束时间、语义目标、允许修正的平移/旋转分量、权重曲线及按身高归一化的最大修正预算。
- `constraints`：约束 ID、种类、目标肢体、道具实例、道具语义点、时间窗、进入/退出淡变和最大权重。第一版约束种类只开放 `secondary-grip`。
- `effectCues`：特效种类、来源道具实例、轨迹或命中语义点、有效时间窗、速度/方向变化阈值和固定寿命。

规范化必须复制输入、稳定排序、限制数组预算、裁剪时间范围、拒绝重复 ID 和非有限数值，并输出中文可诊断结果。扩展参与复杂动作 Clip 哈希；旧资产缺失扩展时保持原逻辑，不自动写回。

### 6.2 道具动作 Rig 扩展

在 `StudioPropAssetV2.extensions` 中新增 `yk-pets/prop-rig/v1`，只描述持械和轨迹需要的语义点：

- `primaryGrip`：主手握点；
- `secondaryGrip`：副手握点；
- `trailStart`、`trailEnd`：轨迹带两端；
- `impactPoint`：命中端点。

每个点使用道具局部 position 与单位 Quaternion。内置星云长棍提供显式值；普通站内参数化道具可按最长主轴、现有 `grip`/`emitter` 锚点和组件边界自动推导。置信度不足时只使用主握点，不阻断道具显示。

### 6.3 只读适配计划

框架无关编译器使用“动作 Clip 哈希 + Rig Profile ID + 模型编译哈希 + 道具资产哈希”生成递归冻结的适配计划。计划包含尺寸化 Warp 目标、约束链、权重曲线、特效源和诊断，不保存 Three 对象或可变运行时状态。

同一输入复用缓存；模型比例、动作或道具变化时键自然变化并重新编译。运行时热路径只采样计划，不重新规范化资产。

## 7. 模块边界

### 7.1 `pet-core`

- 定义并规范化动作适配和道具 Rig 扩展。
- 编译角色、动作和道具语义为只读适配计划。
- 提供与帧率无关的阶段、Warp 权重、约束权重和确定性特效提示采样。
- 不依赖 Vue、Three、DOM、RAF 或墙钟。

### 7.2 Playground Three 适配层

- 新增复杂双足动作适配控制器，消费只读计划和当前动作样本。
- Root Motion Warping 只写角色容器整体 position/Quaternion。
- 主手道具继续由现有 Socket 挂载；副手求解器只写目标手臂链。
- 足底 IK 继续只写腿链；VFX 只读最终道具端点矩阵。
- 所有临时向量、Quaternion 和矩阵复用；不创建第二 Canvas、Skeleton 或 RAF。

### 7.3 Studio Store 与 UI

- Store 提供一次性的“重新自动优化”，只更新当前动作适配扩展并产生一个撤销项。
- 动作基础页显示自动增强状态、预计步幅、双手握持阶段数和特效种类数。
- 时间窗、约束权重、阈值和诊断放入默认收起的“技术信息”。
- 复制内置棍术动作时扩展随资产一起复制并默认启用，用户无需经过向导。

## 8. 运行时所有权与顺序

每帧顺序固定为：

1. 恢复绑定姿态；
2. 采样并写入基础 Quaternion Clip；
3. 采样并绝对写入 Root Motion Warping；
4. 应用现有重心修正；
5. 更新一次世界矩阵，得到主手 Socket 与刚性道具目标；
6. 计算副握点世界目标并求解副手手臂；
7. 执行现有足底 IK；
8. 更新最终骨骼、Socket 和道具矩阵；
9. 采样道具轨迹并更新确定性 VFX。

Root Motion 独占角色容器整体变换；基础 Clip 独占普通局部骨骼姿态；重心只修正既定骨盆/胸腔通道；副手约束只写声明的手臂链；足底 IK 只写腿链；道具变换只由主手 Socket 派生。禁止两个控制器累计写入同一所有权范围。

## 9. 双手握持算法

- 右手作为主手，星云长棍刚体始终由右手 Socket 与 `primaryGrip` 的逆变换确定。
- 左手目标由长棍最终矩阵与 `secondaryGrip` 相乘得到。
- 约束进入和退出使用动作时间驱动的平滑权重，不使用墙钟。
- 求解前按当前臂长、关节限制和最大伸展比例判断可达性；可达时优先使用解析式 Two Bone IK，非标准链回退受约束 FABRIK。
- 副握点不可达时，先沿棍身主轴滑向最近可达区间；仍不可达则按残差降低约束权重并回退单手姿态。
- 求解不得改变任何骨骼局部位置或段长，不得让副手反向驱动主手和道具，从结构上消除循环依赖。

## 10. Motion/Pose Warping

- 现有关键帧保留局部起伏、身体扭转和表演节奏；容器实际位移和转向只来自适配计划。
- 每个 Warp 窗口使用按角色身高归一化的目标差值，并在窗口内通过确定性平滑曲线分配。
- 多个窗口按稳定 ID 和时间排序依次组合；重叠窗口遵守固定优先级并共享帧预算。
- 单帧实际位移、转向和追赶量继续受 Root Motion 安全预算限制，target 与 applied 分离。
- 步幅与朝向修正只影响明确声明的阶段；收势末端回到动作定义的最终位置和朝向，不在最后一帧瞬移。

## 11. 武器轨迹与命中特效

- `weapon-trail`：在棍花和横扫提示窗内，只有 `trailStart`/`trailEnd` 实际速度超过阈值时才保持轨迹带。
- `impact-sparks`：下劈提示窗内，`impactPoint` 穿越尺寸化地面并发生向下速度衰减时触发一次。
- `impact-ring`：与同一合法命中身份绑定，只触发一次尺寸化冲击环。
- 所有信号使用单调 requested time、动作 Clip 身份、窗口 ID 和事件序号形成稳定 ID。
- 轨迹与 burst 使用固定容量对象池；暂停不推进，回拖/reset/dispose 清活动实例和历史采样，不重建 GPU 资源。
- 回拖或显式跳时后不会伪造尚未实际向前经过的旧轨迹；下一次合法向前采样从新时间重新建立历史，因此同一操作序列仍得到同一结果。

## 12. 错误与降级语义

- 动作扩展损坏：忽略适配增强，继续基础 Clip、现有 Root Motion、足底 IK 和原有 VFX。
- 道具 Rig 损坏：继续主手默认挂载，关闭副手与轨迹端点增强。
- 副手约束 blocked：只回退该帧或该阶段的副手，保留主手道具、腿部 IK 和角色容器。
- 轨迹输入非有限：清理该特效类别并记录有界中文诊断，不向 Vue 更新链抛出。
- runtime 替换、动作切换、停止、真实回拖和卸载：按“轨迹 VFX → 副手控制器 → 动作控制器 → 角色 runtime”逆序尽力释放。
- 同一 runtime 的每类写入控制器只有一个所有者；重复创建必须失败并保留原控制器状态。

## 13. 性能与资源预算

- 适配计划在动作/模型/道具身份变化时编译，不在每帧创建。
- 每帧复用 Vector3、Quaternion、Matrix4 和固定数组；禁止按帧复制完整动作、模型或道具资产。
- 武器轨迹和命中特效使用固定对象池，池满时按确定性激活顺序复用最早槽位。
- 不读取 `Date.now()`，不注册独立 `requestAnimationFrame`，不增加 Canvas。
- 诊断采用有界去重集合，避免长时间播放无限增长。

## 14. 新手交互

复制动作后默认自动增强。动作属性“基础”页只展示：

- `自动动作增强：已完成/安全降级/不可用`；
- 预计移动与转向；
- 双手握持阶段数；
- 自动特效种类；
- `重新自动优化` 主按钮。

重新优化由当前动作、模型和道具生成一个可撤销修改，不覆盖其他关键帧、contacts、events、来源字段或未知扩展。普通用户不需要编辑骨骼、握点坐标、Warp 时间窗、速度阈值和粒子数量。

## 15. 测试与验收

### 15.1 领域测试

- 合法扩展规范化、稳定排序、冻结、哈希与 JSON 往返。
- 非有限数值、重复 ID、越界窗口、超预算数组、异常 Proxy 和未知字段隔离。
- 四种体型与星云长棍生成确定且不同的尺寸化计划。
- 旧动作、旧道具和损坏扩展安全回退。

### 15.2 Three 运行时测试

- 可达阶段副手与目标误差不超过角色身高的 `2%`。
- 支撑脚世界残差不超过角色身高的 `0.1%`。
- 骨骼段长误差不超过 `1e-6`，局部骨骼位置保持不变。
- 主手与长棍不分离；副手失败不改变主手、道具、腿链或 Root Motion。
- 暂停、回拖、动作切换、runtime 重建和异常释放均无残留所有权。

### 15.3 特效测试

- 棍影、能量弧、火花和冲击环只在合法提示窗与实际轨迹阈值同时满足时触发。
- 同一输入产生完全相同的信号 ID、数量、强度和生命周期。
- 重复时间、回拖、reset、blocked 和 dispose 不重复生成 burst。
- 对象池容量固定，资源释放幂等且单项释放异常不阻断其他资源。

### 15.4 浏览器验收

Chromium 1440×900 与 760×900 分别检查亮相、棍花、换手、横扫、跳步、下劈和收势；暂停时角色、双手、道具、足底和特效同时冻结；从下劈回拖至棍花不残留冲击环；简单/复杂模式互斥且始终只有一个 Canvas；新手复制后直接播放；窄屏无横向溢出，控制台无 error 或 hydration mismatch。

Safari、Firefox、不同 GPU/WebGL、高细节拓扑和最终像素继续保持未完成状态。
