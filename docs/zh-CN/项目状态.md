## 11. 双足萌宠 Root Motion 与运动特效阶段

- Root Motion 的唯一写入者是复杂模型动作控制器：容器位置按 `绑定位置 + 已求解世界位移` 绝对写入，整体转向按 `世界 Y 轴转向 × 绑定 Quaternion` 写入。持械动作的完整帧顺序固定为绑定姿态恢复、FK、Root Motion、重心、世界矩阵、副手约束、腿 IK、最终矩阵、原运动 VFX、武器 VFX，避免多个系统累计修改同一变换。
- 编辑器保留解析后的播放头给时间轴与道具事件，复杂 runtime 单独消费单调请求时间。循环接缝与 ping-pong 反向不会被误判为回拖；停止、真实回拖、动作切换和异常恢复会同时清理 Root Motion、足底状态与 VFX。
- 当前正式动作范围是行走循环（`.42` 个身高）、冲刺急停挑战（`2.4` 个身高，`6300→8300ms` 制动窗）和起跳与落地（`.28` 个身高跳高）；待机、招手、直拳和其余旧动作默认保持原地兼容。新手界面只暴露原地/实际移动、自动特效、预计距离/转向/跳高和恢复推荐值。
- 运动特效与角色复用同一个 `TresCanvas`。落地环、落地尘点、速度拖尾、急停火花的固定容量为 `8/24/8/24`，总对象槽位 `64`；单次 burst 最多 `16`、活动拖尾最多 `8`、寿命上限 `1200ms`。尘点和火花使用 `InstancedMesh`，不读取墙钟，不注册第二个 RAF。
- `.ai/visual-cases.json` 已记录 `biped-pet-root-motion-motion-vfx` 双视口实测：1440×900 覆盖行走、冲刺、跳跃、暂停/停止/回拖和模式互斥；760×900 覆盖修复后的单列计算样式、跳跃播放控制和模式切换。两者均为 Chromium 功能证据，不得扩大为粒子最终像素或跨浏览器 GPU 结论。
- 正式四足/机甲 Profile、高细节拓扑、Safari/Firefox、不同 GPU/WebGL 和最终像素仍是未完成边界，因此 `crossBrowserGpuManualAcceptanceComplete` 继续为 `false`。
