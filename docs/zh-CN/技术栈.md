# YK-PETS 技术栈详解

## 1. 文档目的

本文说明 YK-PETS 当前实际使用的语言、运行时、框架、主要依赖、构建工具和验证体系，并明确每项技术在仓库中的职责边界。版本以各 Workspace 的 `package.json` 和根目录锁文件为准；本文用于解释选型和使用方式，不替代依赖清单。

## 2. 运行时与工程基线

| 技术 | 当前基线 | 用途 | 约束 |
|---|---:|---|---|
| Node.js | 22+ | Local Agent、Nuxt 服务端、构建和测试脚本 | 不支持低于 22 的运行时 |
| pnpm | 11.13.1 | Monorepo 依赖安装、Workspace 链接和脚本编排 | 使用 Corepack 和 `pnpm-lock.yaml`，不得混用 npm/yarn |
| TypeScript | 5.9.3 | 应用、领域包、配置和脚本的静态类型 | 开启 `strict` 与 `noUncheckedIndexedAccess` |
| ECMAScript Modules | `type: module` | 全仓库模块格式 | 新代码使用 `import`/`export`，不引入 CommonJS 双轨实现 |

根目录 `tsconfig.base.json` 统一使用 ES2022、Bundler 模块解析和严格类型检查。各 Workspace 只补充自身运行环境需要的类型与包含范围。

## 3. Monorepo 与包边界

```text
apps/extension            WXT 浏览器扩展与网页内宠物运行时
apps/playground           Nuxt Playground 和四工作区 Pet Studio
packages/shared           跨扩展与 Agent 的协议、审计、网络和记忆模型
packages/local-agent      本地 WebSocket Agent 与受约束源码补丁
packages/pet-core         框架无关宠物、配方、动作和道具领域
packages/pet-vue-adapter  Vue 3 渲染适配器
packages/pet-web-component <yk-pet> Custom Element 外壳
scripts                   架构契约、文档门禁和专项回归检查
```

依赖方向遵循“应用与适配器依赖领域包，领域包不依赖 UI 和平台 API”：

```text
extension / playground
        │
        ├── pet-vue-adapter ──┐
        ├── pet-web-component ├──> pet-core
        └── shared <──────────┘

local-agent ──> shared
```

`packages/pet-core` 不得依赖 Vue、Nuxt、Chrome API、DOM 或文件系统。`packages/shared` 保存跨执行环境的数据合同，不承载页面状态和渲染细节。

## 4. 前端应用栈

### 4.1 Vue 3

扩展与 Playground 均使用 Vue 3 Composition API。Vue 负责组件组合、响应式状态和界面生命周期，不承载可独立测试的动作求值、资产规范化或网络规则匹配逻辑。

- 扩展固定使用 Vue `3.5.40`；
- Playground 当前使用 Vue `3.5.39`，由 Nuxt 运行时管理；
- Vue 类型检查由 `vue-tsc` 执行。

### 4.2 Nuxt 4

`apps/playground` 使用 Nuxt `4.4.8`，负责文件路由、布局、服务端 API、运行时配置和开发服务器。主要入口包括：

- `/audit-lab`：页面审计实验页；
- `/studio/appearance`：外观工作区；
- `/studio/motion`：动作工作区；
- `/studio/props`：道具工作区；
- `/studio/library`：资产库。

OpenAI API Key 只通过 Nuxt 私有 `runtimeConfig` 在服务端读取，不注入客户端 Bundle。未配置 Key 时，宠物命令接口使用确定性的本地降级逻辑。

### 4.3 WXT 与 Manifest V3

`apps/extension` 使用 WXT `0.20.27` 和 `@wxt-dev/module-vue` 构建 Chrome/Edge Manifest V3 扩展。WXT 管理 Background Service Worker、Content Script、Side Panel、静态资源、Manifest 和打包产物。

扩展权限集中在 `apps/extension/wxt.config.ts`。新增权限必须经过最小权限审查，并同步安全、发布和隐私文档。正式运行状态不得只保存在 Service Worker 内存中，因为 Manifest V3 会挂起并重启 Worker。

### 4.4 Pinia、XState、VueUse 与 GSAP

| 依赖 | 主要职责 | 边界 |
|---|---|---|
| Pinia 4 | Playground 外观、Studio 会话、动作和道具资产状态 | 本地 UI/会话状态，不替代领域规范化函数 |
| XState 5 | Playground 宠物状态机和事件转换 | 不存储长期用户数据 |
| VueUse 14 | 浏览器响应式能力和常用 Composable | 优先复用已有用法，避免封装同类工具 |
| GSAP 3 | Playground 的时间型视觉动画 | 不作为动作资产的领域求值器 |

## 5. 3D 渲染栈

### 5.1 Three.js 与 TresJS

Three.js `0.185.1` 提供几何体、材质、纹理、相机、灯光和 WebGL 抽象；TresJS `5.8.3` 将 Three.js 场景映射为 Vue 组件树。

项目采用程序化 3D 渲染，不依赖远程模型。Studio 导入的本地 GLB 必须满足大小、版本和无外部 URI 限制。

### 5.2 唯一正式渲染器

`apps/playground/app/components/studio/ExtensionAlignedCloudFox.vue` 是唯一正式云狐组合，`CloudFoxStudioCanvas.vue` 是统一预览入口。扩展通过 WXT Alias 复用该实现。

不得复制第二套长期维护的云狐拓扑，也不得为洋葱皮、道具或视觉辅助创建第二个持续运行的 TresCanvas。动作链路为：

```text
StudioMotionAssetV2
  -> normalizeMotionAsset
  -> resolveMotionTime
  -> evaluateNormalizedMotionAsset
  -> EvaluatedCloudFoxPose
  -> CloudFoxStudioCanvas
  -> ProceduralPet
  -> ExtensionAlignedCloudFox
```

动作姿态保存的是相对基础外观挂点的语义偏移，不直接改写外观配方。

## 6. 领域建模与数据验证

### 6.1 `pet-core`

`@yk-pets/pet-core` 提供：

- 物种定义、配方信封和渲染器注册；
- `cloud-fox-semantic-rig/v1` 语义动作通道；
- 毫秒时间、FPS 显示网格和循环模式；
- 动作资产规范化、迁移、插值和确定性求值；
- 关键帧编辑、对称操作和整段修正层；
- 道具实体、组件层级、锚点和事件轨道；
- 高级插值、动作层、IK、音效与安全 GLB 校验。

该包通过 Node 原生 Test Runner 测试，保证不需要浏览器或 Vue 即可验证领域行为。

### 6.2 `shared` 与 Zod

`@nova/shared` 是为 `v0.6.10` 兼容而保留的 Workspace 名称，实际内容属于 YK-PETS。Zod `4.4.3` 用于 WebSocket 消息、服务端结构化输出和外部输入验证。

来自网页、Local Storage、导入 JSON、WebSocket 和模型输出的数据都视为不可信输入，必须先经过 Schema 或规范化函数再进入领域层。

## 7. Local Agent 与源码安全

Local Agent 使用 Node.js、`ws`、Commander、fast-glob 和 `diff`：

- Commander 定义 `yk-pets-agent` CLI；
- `ws` 提供只监听 `127.0.0.1` 的 Token WebSocket 服务；
- fast-glob 搜索受限源码候选；
- `diff` 生成供用户审核的统一 Diff；
- tsup 构建 Node 22 ESM 产物；
- Vitest 验证补丁逻辑。

补丁写入前后使用 SHA-256 检查并保存备份；路径必须保持在显式项目根目录内。Agent 只允许运行项目定义的 `typecheck`、`test` 和 `build`，不得接收任意 Shell 命令。

## 8. OpenAI 集成

Playground 服务端使用 OpenAI JavaScript SDK `6.47.0` 的 Responses API，并通过 Zod Structured Outputs 将自然语言命令限制为已知情绪、动画和安全动作。

此集成属于演示聊天入口，不参与 Local Agent 的确定性源码补丁生成。API 请求失败或未配置凭据时会回退到本地规则，核心 Studio 和扩展能力不依赖远程模型才能启动。

## 9. 构建与验证工具

| 工具 | 用途 |
|---|---|
| vue-tsc / tsc | Vue 与纯 TypeScript 类型检查 |
| WXT | 扩展开发、生产构建和 ZIP 打包 |
| Nuxt CLI | Playground 开发、类型检查、构建和静态生成 |
| tsup | Local Agent ESM 与声明文件构建 |
| Node Test Runner | `pet-core` 的框架无关领域测试 |
| Vitest | Local Agent 单元测试 |
| 自定义 Node 脚本 | 架构合同、品牌、双语文档、动作和视觉数值回归 |

根级验证命令：

```bash
pnpm check:documentation
pnpm typecheck
pnpm test
pnpm build
pnpm build:playground
```

静态门禁和数值测试不能替代真实浏览器验收。涉及布局、交互、WebGL、音频、Side Panel 或 Chrome 权限时，还必须在真实 Chrome 中验证对应视口和操作流程。

## 10. 依赖变更原则

- 优先复用现有依赖和领域能力；
- 新增生产依赖前评估维护状态、许可证、安全记录、包体积和运行时影响；
- 不为简单工具函数引入重型依赖；
- Three.js 在同一页面必须保持单实例，防止类型和渲染上下文分裂；
- 框架适配器保持薄层，核心行为下沉到 `pet-core`；
- 依赖、技术栈或核心命令变化时，同步更新本文、开发指南、架构文档和项目级协作规范。
